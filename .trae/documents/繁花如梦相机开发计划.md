# 繁花如梦相机 · 开发计划

## 一、背景与目标

全新 Android 摄影应用（greenfield，项目目录当前为空）。核心诉求：小米「繁花如梦」风格滤镜、徕卡 M9「一瞬」风格滤镜、1080P 传感器拍出 4K、强防抖、高帧率优化、AI 自动构图、现代简洁界面、丝滑动画，以及 9 语种界面。

已与用户确认的决策：

| 决策项 | 结论 |
| --- | --- |
| 4K 超分落地方式 | 实时超分管线（1080p 采集 → GPU 超分 → 4K 编码）+ 超出硬件能力的帧率用离线插帧补齐 |
| 验证方式 | 安装 Android 模拟器，构建 APK 后安装验证 |
| 界面语言 | 简体中文、繁體中文、English、日本語、한국어、Español、Français、Deutsch、Русский |

产出物：可直接安装的 debug APK（`app/build/outputs/apk/debug/app-debug.apk`），全部代码位于项目目录内，不向桌面等位置散落文件。

## 三、能力边界（将在设置页「设备能力报告」中如实呈现）

1. **4K120 受硬件编码器限制**：普通机型编码器上限通常为 4K30/4K60。实时管线按 `MediaCodec` 能力探测结果输出（4K120 → 4K60 → 4K30 → 1440p 逐级降级），超出部分由离线插帧生成 4K120 文件。
2. **超分为 GPU 边缘导向算法**：EASU 风格边缘自适应上采样 + RCAS 风格对比度自适应锐化（GLES 实时），非神经网络；离线路径预留 TFLite 模型接口。
3. **小米/徕卡滤镜为色彩科学近似**：以曲线、色彩矩阵、柔光扩散、颗粒与暗角组合还原观感，非原厂私有算法。
4. **模拟器只能验证 UI、流程、逻辑与稳定性**；真实画质、高帧率、防抖效果需真机复测。

## 五、里程碑

### M0 工程基线
- 用本机缓存 Gradle 8.7 生成 wrapper，配置根 `build.gradle.kts`、`settings.gradle.kts`、`gradle.properties`、`app/build.gradle.kts`、`AndroidManifest.xml`（CAMERA、RECORD_AUDIO、READ_MEDIA_IMAGES/VIDEO、`android:localeConfig`）、AppCompat 暗色主题基础。
- 验证：`gradlew :app:assembleDebug` 编译通过。

### M1 界面骨架与多语种
- Compose M3 界面：全屏取景器、顶部能力/闪光/设置条、底部模式轮播（照片 / 视频 / 专业 / 超分）、快门、变焦滑块与刻度、镜头切换（0.6x / 1x / 2x / 3.2x，按设备实际焦距生成）、滤镜横向选择条。
- 交互与动效：弹簧动画驱动模式切换与镜头切换、快门涟漪、聚焦环、变焦刻度触感反馈、预测性返回、120Hz 友好的无阻塞动画；控制层毛玻璃。
- 9 语种资源齐全 + 应用内语言切换：`AppCompatDelegate.setApplicationLocales` + `locales_config.xml`，切换后即时重建生效。
- 自绘 SVG 图标集（无 Emoji）。

### M2 相机核心 + 滤镜管线
- `CameraXEngine`：预览、拍照、录像、镜头切换、点击对焦、变焦、闪光、前后摄。
- 自研 GLES 渲染管线：`SurfaceTexture` → 滤镜 Pass 链 → 输出 Surface；基于 `androidx.camera.camera-effects` 的自定义 `CameraEffect`（targets = PREVIEW or VIDEO_CAPTURE）复用到预览与录像；拍照走全分辨率后处理路径，保留 EXIF 与方向。
- 滤镜：繁花如梦（暖调、柔光扩散、低对比高光溢出、微洋红偏移）、徕卡一瞬（M9 CCD 观感：高微反差、深而略抬的黑场、浓郁红黄、青调阴影、颗粒 + 暗角）、原图（对照基准）。
- 硬件防抖：`Camera2Interop` 设置 `CONTROL_VIDEO_STABILIZATION_MODE`（优先 `PREVIEW_STABILIZATION`，保留 OIS）与 `LENS_OPTICAL_STABILIZATION_MODE`，按 `CONTROL_AVAILABLE_VIDEO_STABILIZATION_MODES` 探测可用值。

### M3 AI 自动构图
- `FaceAnalyzer`：`ImageAnalysis` 640x480 + `setOutputImageRotationEnabled(true)` + `InputImage.fromMediaImage`，限流并复用检测器。
- `CompositionEngine`：人脸/主体位置 → 三分法与黄金分割评分，输出最优裁切框与方向提示；实时引导层（网格 + 主体框 + 指向提示）。
- 拍摄时「自动构图」开关：按建议裁切且保持比例，支持一键还原。

### M4 超分与高级录制（Camera2 专业管线）
- `CapabilityProbe`：`StreamConfigurationMap` + `MediaCodec` `VideoCapabilities.areSizeAndRateSupported` 生成设备能力报告（最大录像规格、HEVC 支持、高帧率档位、编码实时性）。
- **超分录制**：Camera2 输出 1080p@高帧率至 `SurfaceTexture` → GL EASU + RCAS 超分至 3840x2160 → `MediaCodec.createInputSurface()`（`COLOR_FormatSurface` + `CONFIGURE_FLAG_ENCODE`）编码，H.265 优先；时间戳取 `SurfaceTexture.getTimestamp()` 并以 `EGLExt.eglPresentationTimeANDROID` 回填，编码器反压时自然阻塞 `eglSwapBuffers`，不硬刷帧；编码能力不足时按 4K60 → 4K30 → 1440p 降级。
- **高帧率慢动作**：`createConstrainedHighSpeedCaptureSession` + `createHighSpeedRequestList` + `setRepeatingBurst`，尺寸取 `getHighSpeedVideoSizes()`、帧率取 `getHighSpeedVideoFpsRangesFor()`，前置条件 `REQUEST_AVAILABLE_CAPABILITIES_CONSTRAINED_HIGH_SPEED_VIDEO`；该会话通常不支持 EIS，按探测结果提示。
- **软件 EIS**：`TYPE_GYROSCOPE` + `SENSOR_DELAY_FASTEST`，`SensorEvent.timestamp` 与帧时间戳（elapsedRealtimeNanos 基准）对齐积分角速度，逆旋转写入纹理矩阵，保留 1.15~1.2x 裁切余量，配低通滤波与延迟标定。
- **拍照超分**：GPU 2x 超分输出 4K 照片，保留 EXIF。

### M5 离线处理与设置
- 离线插帧 `FrameInterpolator`：GPU 块匹配/光流估计生成中间帧，将 4K60 素材输出 4K120，或对高速素材做慢放增强。
- 设置页：语言、输出分辨率与帧率、滤镜强度、防抖/超分/自动构图开关、设备能力报告。
- 稳定性与性能：权限流程、横竖屏、热降频监听（`PowerManager.addThermalStatusListener`）动态降档、MediaStore 分区存储（`RELATIVE_PATH` + `IS_PENDING`）、录像前台服务（`camera|microphone` 类型，由用户可见操作启动）、异常全程降级不崩溃。

### M6 模拟器验证与交付
- 通过 `sdkmanager` 安装 `emulator` 与 `system-images;android-34;google_apis;x86_64`（约 1.2GB，安装至 `D:\Android\Sdk`），`avdmanager` 创建 AVD，先执行 `emulator -accel-check` 确认加速（本机 `HypervisorPresent=True`，若 WHPX 未启用则需管理员开启或降级为纯软件渲染）。
- 安装 APK，逐项截图验证：界面布局、动画、9 语种切换、模式切换、拍照、录像、设置页；检查 logcat 无崩溃与 ANR。若宿主机有摄像头，AVD 相机源设为 `webcam0` 以附带验证人脸检测链路；虚拟场景相机用于其他流程。
- 交付 APK 路径与真机复测清单。

## 六、关键风险与规避

| 风险 | 规避 |
| --- | --- |
| 模拟器 WHPX 加速未启用 | 先 `emulator -accel-check` 检测；不可加速时用软件渲染仅验证 UI 与逻辑，并在交付说明中标注 |
| CameraX 自定义 GL Effect 与厂商 Extensions 冲突 | 不启用厂商 Extensions；若某机型 Effect 初始化失败，自动回退为无滤镜预览并提示 |
| 4K 编码在部分设备不可用 | 全链路能力探测 + 自动降级，绝不硬编码规格 |
| 高帧率会话禁止 EIS / 仅支持单一尺寸帧率 | 录制前探测并给出可用组合，UI 只暴露设备真实支持的档位 |
| 时间戳为 0 或重复导致封装失败 | 时间戳回退策略（`getTimestamp()` → `SENSOR_TIMESTAMP`），GL 线程切换用 `detachFromGLContext/attachToGLContext` |
| ML Kit 在无 GMS 设备 | 检测器初始化失败时自动关闭构图引导并提示，不影响其他功能 |

## 七、验证方式

1. 编译：`gradlew :app:assembleDebug`（首次会下载 Compose、CameraX、ML Kit 等依赖）。
2. 单元测试：滤镜参数表、构图评分算法、能力探测结果解析（JVM 测试，`gradlew :app:testDebugUnitTest`）。
3. 模拟器：安装 APK，截图核验界面与动画，逐语种切换核验文案完整无缺项，logcat 核验无崩溃。
4. 真机（交付后由用户执行）：4K 超分录制、120FPS 慢动作、防抖效果与滤镜观感。
